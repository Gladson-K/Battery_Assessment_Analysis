`model/nas/search.py` runs a constrained PyTorch MLP architecture search over

ReLU, dropout 0.3, 3,457 parameters) with out-of-fold ROC-AUC 0.9644, recall
0.8696, F1 0.8777 and Brier 0.0799. The checkpoint is
`model/generated/nas_best_model.pt`, tracked with Git LFS. The random forest
still has higher ROC-AUC and lower Brier score and remains the firmware model.
See [neural_architecture_search.md](neural_architecture_search.md).

## Intended use

The model is an advisory classifier for the **bench 6 V profile only**. It
distinguishes a safe thermal/electrical state from an unsafe one using eight
temperature channels, voltage, current, analog rain and a digital dry/wet flag.
It is combined with a deterministic rule engine, which remains authoritative.

It is not a BMS, a charger controller, a field-safety certification, or a
replacement for hardware protection. It is not trained or validated for 12 V,
24 V or 48 V packs, for high-current traction systems, or for arbitrary sensor
placements.

## Features and preprocessing

```text
t1..t8      eight temperature channels in C
voltage     battery voltage in V
current     battery current in A
rain_analog analog rain reading (0-1023)
rain_dry    digital dry flag (1 = dry)
```

The firmware replaces missing temperatures with the average of valid channels.
The model self-test runs before inference. If the self-test fails, the result is
marked invalid and the rule engine alone decides.

## Decision policy

- A confident unsafe result (`p_unsafe >= 0.50` and confidence >= 0.65) raises a
  warning floor and contributes 50 % to the combined risk score.
- A low-confidence result contributes only 20 % and does not create an ML-unsafe
  fault.
- The combined score never overrides a hard rule trip.
- Outside the C1 voltage/current domain, the profile-mismatch fault is raised and
  the ML result is discarded.

## Limitations and risks

- Small development dataset; limited coverage of extreme temperatures, sensor
  faults and unusual pack configurations.
- Labels are dataset-provided, not independently verified.
- The model does not see sensor status bits; the rule engine handles open,
  short, stuck and stale sensors.
- The model is trained for the bench 6 V domain. Enabling it on other profiles
  would be an out-of-domain use.
- Random forests are not interpretable per-sample; use the fault mask and rule
  score for diagnostics.
- Quantization/float behavior is deterministic on the tested compiler, but
  re-run parity on any toolchain change.

## Change control

A model change requires:

1. A new dataset snapshot and label audit.
2. Re-training with a fixed split and recorded hyperparameters.
3. A new model version and checksum.
4. Regenerated C header and parity vectors.
5. Host tests, firmware builds and a documented review.
6. A field-validation plan before enabling ML on a new profile.
